# 可验证执行活动

流式卡、Dashboard 和 observe 使用同一份当前轮执行活动投影。投影检查 worker generation、当前 turn 与 dispatch attempt high-water，拒绝旧进程、旧轮或旧重试的执行记录。

真实工具开始事件优先于模型容量排队横幅。没有可验证来源时阶段为 unknown；没有当前轮的开始时间时不编造运行时长，最后活动时间也只来自实际的 CLI 进度事件（输入写入本身不算）。observe v1 的顶层 phase 继续保持 unknown，新事实放在可选 executionActivity 字段。

流式卡只对 traex 显示阶段与本轮耗时（它的原生转写提供阶段事件，卡片此前就有这一行）；其它 CLI 的卡头保持「工作中」，阶段未知时 traex 也显示「工作中」。Dashboard 与 observe 覆盖全部 CLI。

执行活动不并入 lastMessageAt：它仍是最近一次进入会话的输入时间，工作台未读、排序和群秘书判断「巡查期间有没有真人进来」都依赖这个语义。Dashboard 在轮次开始、状态边沿和阶段事件时推送执行活动（离开 working 时清空），页面按渲染时刻推算运行时长与最近活动。

模型输出更新 Dashboard 时每秒最多发布一次；工具事件与生命周期变化立即更新。已完成、非工作态或探测失败的会话不携带旧执行事实。改变展示与观测投影，不改变输入投递的认领、回执和重试状态机。
